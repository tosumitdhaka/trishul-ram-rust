# RUN+ISO-001 measurement and safety plan — precommit only

**No trial executed.** All timers must use a monotonic nanosecond source; a cross-process trace may never assume independent clocks have zero offset unless their common kernel clock and mapping are explicitly proved. Require a per-process monotonically increasing sequence and stable PID/start generation. Commit SHA and input-tree fixture SHA must accompany every trace.

A **source unit** is the useful throughput unit: one unit counts only once **both** required A and B scratch receipts are committed under its immutable source/attempt/effect identity. `confirmed useful throughput = fully confirmed units / elapsed seconds` (also report confirmed records/s = 8 × units/s). Units with filtered/failed/UNKNOWN outcomes are **not** useful confirmations and must be included in correctness denominators. p99 is the nearest-rank p99 of `(both required receipts committed monotonic ns - source-unit admission monotonic ns)` for successful no-fault units; report `n`, while separately listing every failed/unknown/incomplete unit and its outstanding source guard. Time window includes the same first-admission to last terminal-or-held-obligation boundaries in all 2×2 cells.

For actual I/O overlap, record `effect_start` immediately before the operation and `effect_end` after its blocking/awaited completion. Pair by exact `(run,source_unit,branch,effect,batch)` and compute the interval intersection in monotonic nanoseconds. Configured concurrency alone is not evidence. Baseline A×I, 3 clean trials/cell and identical 4-core CPU quota/disk/sample profile must be pinned. B delay is **per 8-record batch**, never per record (50 ms normal; 250 ms stalled; separately fully blocked). Scheduler is the deterministic ascending two-run round-robin recorded in `schedule.json`.

Sampler runs every **100 ms** and additionally at each fault edge. Read `/proc/<pid>/status` `VmRSS` and `VmHWM`, `/proc/<pid>/fd` count, scoped cgroup quota, queue and journal occupancy. Measure each manager, worker and descendant process separately and a sum; don't conflate a sum of noncoincident peaks with instantaneous peak. Capture final/last-before-kill `VmHWM` when possible, the sampling gaps, and exact inaccessible process/PID errors. Caps: <=256 MiB summed VmHWM, <=128 FD/process, <=256 total; per-run charge <=64 MiB and shared <=128 MiB; per branch <=64 queue entries/4 MiB and total <=256/16 MiB; <=4 active blocking operations, <=4 blocking threads and <=16 pending jobs. Every unobserved metric stays INCONCLUSIVE (never silently 0).

Availability/fairness: count only branch dequeues while **both** runs are runnable and queued. Each full 5-second eligible window must give both runs >=20% of opportunities; each runnable queued run must progress at least once every 2 seconds. Cancellation: from signal edge until stopped *new ingress* and wake of all permit waits <=2 seconds, not until blocked OS effects stop. Blocked fsync control must answer with pending/UNKNOWN <=3 seconds without invented quiescence; old worker plus descendants verified unable to write <=5 seconds before replacement may be permitted. Nonregression vs A×I with matching tiers: >=80% useful units/s, <=2× baseline p99 and <=1.5× summed aggregate VmHWM; CPU-seconds/confirmed unit and open FDs reported separately.

Capture raw JSONL with v1 schema (never log credentials), stdout/stderr, exact exit status or signal, sorted file-hash inventory of scratch output, manager and worker journal/outbox snapshots, receipt/guard/frontier before and after each fault, code/fixture hashes, cgroup and mount metadata. Store SHA-256 of **exact JSONL bytes** plus byte length and source code SHA. Cleanup allowlist must be exact separately created test-root paths plus owned test PIDs/cgroup, never wildcard kill/purge or production directories. These are prospective Stage B requirements, not measurements made by this change.
